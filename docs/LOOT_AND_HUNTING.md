# Gear, rare/ex drops, and notorious monsters

Three more databases, generated by `tools/gen_loot.py` from the same LandSandBoat checkout as
the quests (`docs/QUEST_DATABASE.md`), and one lookup layer that turns any row of them into a
step the arrow points at.

| file | what is in it |
| --- | --- |
| `data/nm.lua` | **365 notorious monsters** — zone, level range, respawn, recorded drops; **112 with a real spawn point** |
| `data/drops.lua` | **110 items** with the mobs that drop them and the server's own drop rates |
| `data/vendors.lua` | **1,167 items** somebody sells, with the merchant, the zone and the price |
| `data/gear.lua` | **485 equipment pieces that have a source you can be pointed at** — level, jobs, slot, rare/ex |

## Using it

```
/vg find scorpion harness     what drops or sells it, best source first
/vg gear head                 head pieces your job can wear at your level, with sources
/vg nm                        notorious monsters in this zone
/vg nm lizzy                  by name
/vg track 3                   point the arrow at result 3
```

`/vg track` builds a one-step guide on the spot, so a lookup answer *is* a guide — the same
router, the same arrow, no second navigation path in the addon. There are also generated
hunting guides, one per zone that has notorious monsters with known spots ("Notorious
monsters — Valkurm Dunes"). Those steps are `FIXED`: hunting is not a sequence, so nothing
auto-completes and the list stays where you left it.

## What the data does and does not cover

Read this before trusting a blank result.

* **Drop tables are thin.** LandSandBoat's public `sql/mob_droplist.sql` holds 187 drop lists
  for the whole game — real, correct, and nowhere near complete. Most private servers import
  a fuller table from elsewhere. So "nothing drops it" in Vanaguide means *the open server
  data does not say what drops it*, not that nothing does.
* **A third of notorious monsters have no coordinates.** LandSandBoat writes `(1,1,1)` when a
  script decides where something spawns. Those entries keep their name, level and drops and
  lose their position rather than aiming the arrow confidently at the middle of nowhere. The
  generator strips them and the harness asserts none survive.
* **Vendors mostly have a zone, not a spot.** Shops live in zone scripts rather than a table,
  and `npc_list` only holds part of the world, so a merchant usually resolves to "in Norg"
  and the router takes you to the zone.
* **Names come from the server**, so they read as the server writes them.

## Pathways for making it complete

1. **A fuller drop table.** Any server database Daniel can legitimately read — his own
   LandSandBoat instance after importing a community drop set — regenerates this in seconds:
   the generator takes a checkout path, and pointing it at a populated `sql/` is the whole
   change.
2. **Quest and synthesis sources.** `quest.reward.item` is already parsed for key items and
   could add "this comes from quest X"; `sql/synth_recipes.sql` would add "you can craft it".
   Both are a table join away and would raise gear coverage far above 485 pieces.
3. **Spawn points for the missing notorious monsters.** They are in the zone scripts that
   spawn them (`scripts/zones/*/mobs/*.lua`), as positions passed to the spawn helpers.
4. **A wiki adapter, at runtime, not in the repository.** The same shape as CompletionRoute's
   WoW-Pro adapter: read a dataset the player installed themselves rather than redistributing
   somebody else's NC-licensed text. See [QUEST_DATABASE.md](QUEST_DATABASE.md).
