# Unattended verification — 2026-09-11

A character on the local LandSandBoat world was driven through the San d'Oria quest guide
unattended: teleport/walk to each step, talk to the NPC, the narrator (VanaVoice) reads the
dialogue aloud, `/vg advance` releases the event, and the server's quest log is checked. This
file records what was proven, what failed, and the pathways a future session should use.

## What was verified live

- **Full guided loop (teleport mode)** — guide 10 "San d'Oria - every quest":
  - Step 25 *Grimy Signposts* (Maugie): talk at 0.7y → 3 dialogue lines → **3 narrator lines
    spoken** (`say [narrator]` in VanaVoice log) → event 45 released → server:
    `quest ID 66 is: ACCEPTED`. The whole chain, end to end.
  - Step 28 *The Merchants Bidding* (Parvipon): same chain; quest stayed AVAILABLE because it
    wants 3 rabbit hides first — correct game behaviour, not a bug.
- **Narrator**: one generic voice for everything (`en_US-ryan-high`), the 1.5 default. Dedup
  ("already said within 20s") works. Spoke the login system line and both NPC lines.
- **Zone-line walking**: the client crossed Northern→Southern San d'Oria on its own
  (`walk: arrived (Go to Southern San d'Oria)`) — follow-runner + zone crossing still work.
- **The Mac-side harness pipe** (new): the whole run was driven through
  `/tmp/ffxi-pipe/cmd.txt` + `chat.txt` — see "TCC" below.

## What failed, and why

1. **CORRECTION (post-run): navgrids are PRESENT and navmesh pathing works.** A later
   `/vg status` showed `path navmesh` and `navmesh: zone 231, 236x204 … 2 floors, done
   (4203 cells searched)`. The earlier `navmesh: none loaded` is what Nav.status() prints
   BEFORE the first path request — grids load lazily. The step-5 walk that "arrived" at
   57.8y did so because the step was already `mode=here` (inside the here-radius), so the
   walker's contract was met; the real gap is that the here-radius (~60y) is wider than
   talk range (~6y) — the walker should close to talk range when the step has an NPC.
2. **Cross-zone teleports in guided_run**: `!pos` into another zone during the settle window
   is dropped silently (known trap); steps 26/27 never arrived and were misses. guided_walk's
   22s wait handles it; guided_run should too.
3. **Launcher window never appears** when launched `open --args` unactivated on macOS 26 —
   filed as HorizonXI-on-Mac issue #27, workaround: second `open -a` ~5s later.
4. **Screen lock**: window screenshots fail while the Mac is locked; the run's evidence is
   RESULTS.md + chat + narrator log for those stretches. The game keeps rendering and the
   pipe keeps pumping while locked.

## The TCC situation (read this before driving anything)

Terminal lost its removable-volume grant to `/Volumes/x10` (it returns EPERM for every read
and write, Finder can list but NOT write, and the grant only comes back after Terminal is
fully quit and reopened — no in-session fix). Consequences and the pathway that works:

- The game dir, installed addons, `~/Games/lsb` (server tree, logs, `.dbpass`) are all
  unreachable from the driving session.
- **Launch** through the launcher app instead (it has its own grant):
  `open -a HorizonXI.app --args --play --world "Local server"`, then `open -a HorizonXI.app`
  again to defeat the window bug. It starts mariadb + the four xi_ servers + the client.
- **Drive** through the Mac-side pipe: `/tmp/ffxi-pipe/cmd.txt` (commands) and `chat.txt`
  (mirrored chat). The pipe block currently rides in the vanavoice addon
  (vanavoice PR #6) because the launcher re-installs that addon from
  `/Applications/VanaVoice.app` on every Play; the same block is in cmdpipe upstream via
  HorizonXI-on-Mac PR #26. Create `/tmp/ffxi-pipe/cmd.txt` BEFORE launching or it stays
  disarmed.
- **Database** is reachable: `mariadb -u daniel` (unix_socket DBA), db `xidb`, chars Test(1)
  and Buddy(2). `brew services start mariadb` if it is down — the launcher's status calls
  the DB "still to do" when mariadb is simply not running.
- The adapted harness scripts live in the session scratchpad as `guided_run_pipe.sh` /
  `guided_walk_pipe.sh`: identical to tools/guided_run.sh/guided_walk.sh with
  CMD/CHAT pointed at /tmp/ffxi-pipe.
